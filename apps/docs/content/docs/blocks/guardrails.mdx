# Guardrails Block

The Guardrails block validates content against a chosen rule before it moves downstream. It can check whether content is valid JSON, matches a regex pattern, detect hallucinations using RAG + LLM scoring, or detect (and optionally mask) PII. Reach for it when you need to gate or sanitize text inside a workflow.

## Overview

| Property | Value |
|----------|-------|
| **Type** | `guardrails` |
| **Category** | blocks |
| **Color** | `#3D642D` |

## When to Use

- Verify that an upstream block produced syntactically valid JSON before parsing it.
- Confirm content matches a specific format (email, phone, URL, date, custom pattern) via regex.
- Fact-check an AI response against a knowledge base and score it for hallucinations.
- Detect personally identifiable information (names, emails, phone numbers, Aadhaar, PAN, credit cards, etc.) for privacy compliance.
- Mask PII in place so sensitive data is scrubbed before storage or sharing.
- Block requests that contain disallowed personal information.

## Configuration

### Content to Validate

The `input` field holds the text to validate. Accepts references like `{{blockName.output.fieldName}}`. Required.

### Validation Type

The `validationType` dropdown selects the rule: `json`, `regex`, `hallucination`, or `pii`. This drives which other fields appear.

### Regex Pattern

When validation type is `regex`, the `regex` field holds the pattern to match against (e.g. `^\{.*\}$`).

### Knowledge Base, Model & Threshold

For `hallucination` checks: `knowledgeBaseId` selects the knowledge base for context, `model` picks the LLM for confidence scoring, `threshold` (0-10 slider) sets the minimum passing score, and `topK` controls how many context chunks are retrieved. `apiKey` (plus optional `azureEndpoint` / `azureApiVersion`) supplies provider credentials.

### PII Settings

For `pii` detection: `piiEntityTypes` selects which entity types to detect (leave empty for all), `customPiiPatterns` adds custom JSON-defined patterns, `piiMode` chooses `block` or `mask`, and `piiLanguage` sets the detection language.

## Inputs & Outputs

- **Inputs**: `input` (string), `validationType` (string), `regex` (string), `knowledgeBaseId` (string), `threshold` (number), `topK` (number), `model` (string), `apiKey` (string), `azureEndpoint` (string), `azureApiVersion` (string), `piiEntityTypes` (json), `piiMode` (string), `piiLanguage` (string), `customPiiPatterns` (json)
- **Outputs**: `passed` (boolean), `validationType` (string), `input` (string), `score` (number), `reasoning` (string), `detectedEntities` (json), `maskedText` (string), `error` (string)

## YAML Example

```yaml
guardrails-1:
  type: guardrails
  name: "Guardrails"
  inputs:
    input: "{{agent.output.content}}"
    validationType: "pii"
    piiMode: "mask"
    piiLanguage: "en"
  connections:
    outgoing:
      - target: next-block-id
```
