# Credential Block

The Credential block looks up OAuth credentials stored in your account, either by their unique ID or by listing all credentials for a given provider. Reach for it when a workflow needs to select credentials dynamically at runtime instead of hard-coding secrets.

## Overview

| Property | Value |
|----------|-------|
| **Type** | `credential` |
| **Category** | blocks |
| **Color** | `#3B82F6` |

## When to Use

- Resolve a stored OAuth credential to its access token for use in a downstream API call.
- Dynamically pick a credential by ID that was supplied earlier in the workflow.
- List all credentials tied to a specific provider (e.g. google, github) to drive branching logic.
- Count how many credentials of a provider are available before proceeding.
- Avoid hard-coding secrets by referencing credentials by ID instead.

## Configuration

### Operation

Choose what the block does: `Select credential by ID` retrieves a single credential, while `List credentials by provider` returns all matching credentials. Defaults to `select`.

### Credential ID

The unique identifier of the OAuth credential to retrieve. Required when the operation is `select`.

### Provider Filter

An optional provider ID used to filter the returned credentials (e.g. `google`, `github`). Shown when the operation is `list`.

## Inputs & Outputs

- **Inputs**: `operation` (string), `credentialId` (string), `provider` (string)
- **Outputs**: `credentialId` (string), `displayName` (string), `providerId` (string), `token` (string), `credentials` (json), `count` (number)

## YAML Example

```yaml
credential_1:
  type: credential
  name: "Credential"
  inputs:
    operation: "select"
    credentialId: "cred_xxxxxxxxxxxxxxxx"
  connections:
    outgoing:
      - target: next-block-id
```
